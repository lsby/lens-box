# lens-box

### 告别“上帝视角”：构建多视角、可演化的个人 AI 认知工具箱

> **“不存在绝对的唯一模型，只存在适配当前场景的最佳视角。”**

`lens-box` 是一个基于 TypeScript 与 pnpm workspace 构建的多视角认知算法库集合（Monorepo）。每一个子包（Lens）都是一个独立实现的底层算法库，专注于将人类各学科的观察直觉，沉淀为特定视角下可调用的分析与建模能力。

---

## 一、 问题的起源：当我们在为 AI 建模时，我们在害怕什么？

今天，几乎所有试图让 AI 变得更懂人类、更有个性的探索——无论是模仿细腻的文学笔触、构建拟人化的长期记忆，还是赋予 AI 自主探索世界的行为逻辑——最终都会撞上同一堵墙：**我们该如何向 AI 描述这个复杂的世界？**

过去，工程界最习惯的做法是“大一统建模”：

- 想让 AI 写好文章？那就设计一张包含“性格、情绪、背景、句式”的超级属性表，试图用一套完美自洽的框架穷尽所有文风。
- 想让 AI 拥有记忆与人格？那就建一套涵盖“身份设定、人际亲疏、兴趣偏好、情绪权重”的固定记忆模型，规定好每段经历该归入哪个标签、重要度打几分、何时触发遗忘。

然而，只要真正动手做过，就会立刻感受到一种强烈的不安：**一旦框架定型，系统就被“写死”了。**

人类世界本身是流动、矛盾且多维的。一套在“悬疑小说”里极其好用的情绪张力模型，放到“日常闲聊”或“古典散文”里可能完全失效；一套在“理性决策”中表现优异的逻辑框架，放到“感性陪伴”里反而会显得生硬机械。如果强行用一套单一的静态标准去丈量所有事物，本质上是在用开发者个人的认知局限，去阉割大模型原本具备的广阔可能性。

## 二、 核心哲学：模型论与“多透镜”世界观

`lens-box` 的诞生，源于一种朴素的模型论（Model-dependent Realism）直觉：

在物理学中，观察苹果落地，牛顿给出了“万有引力”模型，爱因斯坦给出了“时空曲率”模型。我们不能武断地说哪一个才是“绝对真理”，只能说：**它们是对同一个客观现象的不同建模；在解决具体问题时，我们会选择最契合当前场景的那一个。**

理解人类语言、心理与行为也是如此。一篇文章、一段对话或一次决策，从来不只有一种解释方式：

- 用**心理学视角**去看，你看到的是人物性格、权力博弈与社交距离；
- 用**语言学视角**去看，你看到的是长短句节奏、虚实词分布与修辞密度；
- 用**社会学或人类学视角**去看，你看到的是群体暗号、时代语境与文化隐喻。

这些视角之间没有谁比谁更“高级”，它们也不需要被强行揉捏进一个所谓的“最小认知基本单位”里。**它们是彼此平行、互不覆盖的独立维度。**

## 三、 架构定位与边界：`lens-box` 做什么，不做什么

为了保持每个视角的纯粹性与可复用性，`lens-box` 在工程上坚持清晰的职责分层：

- **`lens-box` 是底层的“视角算法原语库”**
  - 仓库中的每个子包（位于 `package/` 下）都是一个独立的初级算法库，专注于实现某一种特定视角下的观察、分析、特征提取或结构化建模算法。
  - 每个包内部完全自治：它可以自行决定所需的技术栈与依赖，既可以是纯文本/统计分析算法，也可以基于 OpenAI 兼容协议（如 `@lsby/ai-agent`）实现提示词与结构化提取逻辑，还可以包含自身所需的数据结构、存储与查询方法。
- **上层调度与集成由主项目负责**
  - `lens-box` 中的透镜包**不负责全局 AI 自主调度或业务流程编排**。
  - 引入这些库的上层主项目，可以根据自身需求对其进行二次包装（例如封装为 Agent Tool、MCP Server、Workflow 节点等），并自行决定数据如何共享、如何建立索引让 AI 发现与自主调度。

通过这种“底层视角算法库 + 上层自由编排”的解耦设计，我们希望推动三个核心转变：

1. **从“单一大脑结构”转向“平行视角集合”**：不再试图设计包罗万象的超级模型，而是将每一种独立的观察维度沉淀为小巧、纯粹的透镜库。视角可以无限增加，彼此互不干扰。
2. **从“人类预设规则”转向“AI 自主调度与涌现”**：当上层主项目把足够多独立的透镜摆在 AI 面前时，不再替它规定“遇到什么问题必须用什么框架”，而是交由 AI 根据具体语境自主选择、甚至交织看似矛盾的多个视角，激发出组合泛化与涌现能力。
3. **从“闭门造车”转向“原子能力共享”**：无论上层应用最终想打造极致文风、长期记忆还是自主生活，底层都可以复用同一批跨学科的观察工具，并借助不断扩充的工具箱实现个人 AI 自身的持续演化。

## 四、 仓库结构

```text
lens-box/
├── package/                 # 独立透镜包目录（每个子目录为一个独立算法库）
│   ├── psychology-style-lens/
│   └── semantics-lens/
├── AGENTS.md                # 仓库开发导览与工程化规范
├── package.json             # 根工程脚本与共享开发依赖
├── pnpm-workspace.yaml      # pnpm workspace 配置
├── tsconfig.base.json       # 共享 TypeScript 严格编译配置
├── eslint.config.mjs        # 共享 ESLint 配置（基于 @lsby/eslint-config）
├── .prettierrc              # Prettier 格式化与 import 排序配置
└── .prettierignore          # Prettier 忽略规则
```

## 五、 快速开始

### 环境要求

- Node.js >= 20
- pnpm >= 9

### 安装依赖

```bash
pnpm install
```

### 常用命令

```bash
# 一键格式化、自动修复 ESLint 并执行类型检查
pnpm tidy

# 严格只读检查（格式检查 + ESLint + 类型检查 + 构建）
pnpm check

# 单独执行各阶段命令
pnpm format
pnpm lint
pnpm typecheck
pnpm build
```

## 六、 新增一个透镜

1. 在 `package/` 下创建一个以英文小写短横线命名的新目录，例如 `package/psychology-character-lens/`。
2. 参考现有透镜包（如 `package/psychology-style-lens/`）配置 `package.json`（包名建议使用 `@lsby/lens-box-<lens-name>`）和 `tsconfig.json`。
3. 遵循 [AGENTS.md](./AGENTS.md) 中的编码与类型约定编写透镜算法，尽量减少对外部基础设施的硬耦合，并在该包的 `README.md` 中清晰说明：
   - **观察视角**：该透镜关注什么维度的问题。
   - **核心领域概念**：该视角下抽象出的核心领域对象、模型结构及其各自承担的职责与能力。
   - **适用边界**：该视角擅长与不擅长的场景。
4. 在根目录运行 `pnpm tidy` 与 `pnpm check`，确认所有检查通过。

## 结语

`lens-box` 不是一个试图定义一切的庞大框架，也不是某个单一垂直产品的附庸。它是一场关于“观察方式”的长期实验，更像是一座不断扩充的**认知工具博物馆**。

每一个新视角的加入，都是为 AI 打开的一扇新窗户。窗户开得越多，它离理解真实的人类世界就越近一步。
