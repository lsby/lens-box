# 表达成团透镜的测试结果

## 同样出现八次，会得到什么分数

八份合成工单都有六种例行记录，每种各出现一次。另外，“返修”在四份工单里各出现两次，“釉裂”在两份里各出现四次。每个读数单独一行，便于手算。按默认配置，该同频桶有八个不同参照，泊松期望覆盖 5.057 篇，按这批表单校准后为 8 篇。

| 表达 | 总次数 | 覆盖工单 |             成团分数 |
| ---- | -----: | -------: | -------------------: |
| 签收 |      8 |        8 |                0.000 |
| 返修 |      8 |        4 |                0.693 |
| 釉裂 |      8 |        2 |                1.386 |
| 缺角 |      1 |        1 | 无分数，出现不足三次 |
| 换轴 |      0 |        0 |       无分数，未出现 |

例如“釉裂”的计算是 `ln(8/2) = 1.386`。输出还保留了工单序号，可以直接定位到第 0 和第 1 份工单，各出现 4 次。

## 反例：语言切换也能造成集中

另造八份日文和八份中文表单，篇幅相同，共享十二个字段代码。各语言另有六个固定字段，每个在本语言的每份表单中恰好出现两次。“点検”是日文表单的常规字段。两次查询使用完全相同的十六处“点検”，只改变建立参照的语料。

| 参照语料     | 文档数 | 总次数 | 覆盖篇数 | 校准期望篇数 | 成团分数 |
| ------------ | -----: | -----: | -------: | -----------: | -------: |
| 两种表单合看 |     16 |     16 |        8 |           16 |    0.693 |
| 仅日文表单   |      8 |     16 |        8 |            8 |    0.000 |

这个例子里的集中完全可以由表单语言解释。只看混合语料的分数，就可能把固定字段读成话题信号。分组复算是一种核对方式，实际工作中应按研究问题决定是否控制语言。

## 复现

以上正文由确定性的合成生成器直接构造，可以公开逐行核算。[工单与双语表单](./demo/synthetic-corpus.ts) · [可执行断言](./test/clumping.test.ts)

在 lens-box 根目录运行。验证环境为 Node.js 26.3.0、pnpm 9.5.0，上游版本 `dbee564`。

```sh
pnpm install --frozen-lockfile
pnpm --filter @lsby/lens-box-expression-clumping-lens test
pnpm --filter @lsby/lens-box-expression-clumping-lens demo
pnpm check
```

本轮运行通过 9/9 项测试。工作区的格式检查、ESLint、类型检查及全量构建均通过。九项测试覆盖同频表达的手算值、负分、逐篇计数、缺少参照、上下档等距、上中位数、Unicode 重叠与边界、固定种子复算及非法输入。`demo` 逐行输出这两张表对应的完整 JSON。

## 原应用的公开汇总

Hikaru 另有一次按天切分的历史回放，共 30 个有记录的日子、1,891 条发言。在原有入口规则上增加“一般语言中常见、本地分布较散、出现超过六次”这个联合条件后，会递送旧材料的发言从 100 条降到 64 条。64 条中 34 条被判有用。新规则移除的 37 条中，旧报告估计约有 4～5 条原本有用。该回放在同一份材料上探索参数，其结果用于说明联想入口的实际取舍。新 TypeScript 包的验证使用上面两组合成材料。[原报告与统计口径](https://github.com/ikarugaikoi/hikaru-memory/blob/main/docs/limitations.md)
